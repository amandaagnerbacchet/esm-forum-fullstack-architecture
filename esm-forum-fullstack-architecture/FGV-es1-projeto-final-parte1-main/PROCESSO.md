# Processo Ágil - Escolha e Estruturação do Board

## Escolha do Board: Kanban
Para o desenvolvimento deste projeto, optamos pela metodologia **Kanban**. 

### Justificativa
O Kanban é ideal para este projeto pelas seguintes características:
- **Fluxo Visual Contínuo:** Permite visualizar claramente o status de cada tarefa (A Fazer, Em Progresso, Concluído).
- **Flexibilidade:** Facilita o gerenciamento de tarefas sem a rigidez de ciclos de Sprints fechados, otimizando o tempo.
- **Foco no WIP (Work in Progress):** Ajuda a concentrar esforços em concluir uma funcionalidade de cada vez.

## Estruturação do GitHub Projects
O board foi configurado com as seguintes colunas:
1. **Backlog / A Fazer:** Onde estão cadastradas as 5 novas funcionalidades solicitadas.
2. **Em Progresso (In Progress):** Tarefas em desenvolvimento.
3. **Revisão / Testes (Review):** Validação dos códigos.
4. **Concluído (Done):** Funcionalidades finalizadas.

### Ordem de Prioridade dos Cards (Backlog)
1. Sistema de votação em perguntas (upvote/downvote)
2. Busca de perguntas por palavra-chave
3. Categorização de perguntas (tags)
4. Perfil de usuário com histórico
5. Notificação de novas respostas
